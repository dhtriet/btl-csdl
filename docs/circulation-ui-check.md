# Circulation UI extension check

Date: 2026-11-10. Scope: desktop at 1024px and 1440px. Verdict: the five teacher-feedback additions extend the existing Pink Glam application; they do not establish a new visual system. Preserve `DESIGN.md` and `.impeccable/design.json` unchanged.

Reviewed `public/assets/circulation-desk.css`, `public/assets/circulation-desk.js`, the integration in `public/views/app.php`, and the current design specification/sidecar. The new stylesheet follows Pink Glam in the cascade and adds local component layout without replacing palette, font families, panel geometry or shell rules.

| Addition | Comparison with incumbent Pink Glam |
| --- | --- |
| Inventory reconciliation | Reuses the ordinary glass `.panel`, `.panel-heading`, `.data-table`, `.text-button`, `.stack-form` and magenta `.primary-button`. The inline editor is separated by the existing rose line token and 24px spacing. Discrepancies and unverified stock use `--danger` plus explicit wording; quantities remain labelled as available, on loan and unavailable. The adjustment table is read-only. |
| Full account details | Opens an inline, labelled panel beneath the account list, rather than introducing another modal or page composition. Definition lists pair muted 12px labels with plum values. Student borrowing and librarian handling/extension histories reuse the same ruled tables and quiet trace/receipt links. Missing values remain explicit. A close action returns to the account list. |
| Request/receipt trace | Reuses an ordinary panel, visible form labels, a compact primary action and an inline result separated by a rose rule. Definition lists distinguish source, status, handler and dates; the receipt table preserves per-resource quantities and deadlines. Unlinked legacy records and requests without receipts display explanatory text rather than inferred provenance. |
| Counter lending | Uses native `details`/`summary`, matching the existing learning-kit disclosure approach, with an 18px summary title. Forms keep labelled selects, quantity/date fields, a quiet add/remove action and one magenta submission action. Supporting text explains the actual transaction; the polite result region offers a trace link. The disclosure is presented for librarians. |
| Normalization documentation | `docs/normalization.md` is a technical artifact, not a new application surface. It requires no visual tokens, component variants or decorative treatment. |

Typography remains the existing self-hosted Manrope/Be Vietnam Pro pairing. The extension adds no font family, color literal, radius, shadow or animation. Its 12–13px form/definition labels fit the incumbent metadata scale. Table captions now use 18px at weight 700, aligning their size with the established panel-title role; the earlier 17px detector advisory was resolved in code rather than promoted into a new token.

The 12px/16px/24px gaps and section spacing follow the incumbent rhythm. Local 18px table/definition spacing and 6–7px label gaps are component-level measurements, not additions to the global spacing scale. At 1000–1200px, counter rows keep resource/quantity/date in three columns and move removal to its own row; definition lists reduce from three columns to two. Tables retain the existing horizontal overflow wrapper. These changes fit the available desktop content width without altering sidebar or header dimensions. Phone redesign is outside this check.

The controls inherit existing field surfaces, magenta keyboard-focus treatment and disabled states. Native disclosure behavior, associated labels, `dl`/`dt`/`dd`, table captions/headers, loading status text and polite result regions preserve semantic distinctions. Detail headings receive programmatic focus where implemented. This comparison does not replace a complete keyboard or assistive-technology audit. Existing global sparkle effects and their pause/reduced-motion behavior remain unchanged; the extension introduces no additional decorative loop.

Desktop evidence is stored in `.impeccable/review/circulation/`: `account-student-1440.png`, `account-librarian-1440.png`, `counter-1440.png`, `counter-1024.png`, `trace-1024.png`, `inventory-1440.png` and `inventory-1024.png`. The supplied review validated these views; direct documentation spot-checks of the librarian details, 1024px counter and 1440px inventory captures agree with the source comparison. No approved system change was found, so this report is the documentation outcome rather than a rewrite of the design specification.
